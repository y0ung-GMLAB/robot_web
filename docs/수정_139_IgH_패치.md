## 0. 왜 이렇게 고치나 (한 단락)

드라이브 전원 재투입·재스캔 뒤 IgH 마스터가 슬레이브마다 **SDO 사전(SDO-Info)을 저절로 읽는다**(`master/fsm_master.c:627-650` · PREOP 뒤 3 s · 한 대씩). 이 읽기는 **마스터 FSM** 의 fsm_coe · 우리 `ethercat upload/download` 는 **슬레이브 FSM** 의 fsm_coe(`master/fsm_slave.c:240-283`) · 둘 사이에 **메일박스 잠금이 없다**(1.6.9 소스에 없음 · 확인함) → 서로 SM1 응답을 가로채 「wrong SDO (0x3015 ↔ 0x603F)」 · 「unknown response」 · 결국 드라이브 메일박스가 멈춤(제어 전원 재투입으로만 풀림). 우리 쪽 flock(`ethercat_mailbox.py`)은 커널 안쪽을 못 막는다. 우리는 사전을 **안 쓴다**(모든 호출이 `-t` 로 타입을 준다) → **사전 읽기를 끄면 원인이 없어진다.** 끄면 잃는 것 · `ethercat sdos` 목록 · `ethercat upload` 를 `-t` 없이 쓸 때 타입 추정 · PDO 이름 표시뿐.

## F. 배포 (PC 마다 · 사람 · sudo)

웹 업데이트로는 커널 모듈이 안 바뀐다. 코드를 「모든 PC 업데이트」로 먼저 내린 뒤 **각 PC 에서**:

1. 모터 정지 확인 (재생·조그 없음) · 서보 오프
2. `systemctl --user stop motion-motor.service` (모터 프로그램이 마스터를 잡고 있으면 rmmod 실패)
3. `sudo /usr/local/sbin/ethercat-rebuild --force` (C 완료 뒤) · 또는 `bash scripts/install.sh --site` 의 EtherLab 단계
4. `sudo systemctl restart ethercat`
5. 확인 · `modinfo -p ec_master | grep sdo_dict` 줄 있음 · `cat /sys/module/ec_master/parameters/sdo_dict` = `0` · `ethercat slaves` 에 3 대 OP 전 상태
6. `systemctl --user start motion-motor.service` · 웹에서 3 대 OP·앱솔루트 확인 정상
7. 커널 업데이트 뒤 재부팅 한 번 해서 `ethercat-rebuild.service` 가 패치된 모듈을 다시 만드는지 (`journalctl -u ethercat-rebuild -b`)

되돌리기 · 다시 빌드 없이 `echo 1 | sudo tee /sys/module/ec_master/parameters/sdo_dict` (다음 재스캔부터 원래대로) · 영구로는 `/etc/modprobe.d/ethercat.conf` 에 `options ec_master sdo_dict=1`.
